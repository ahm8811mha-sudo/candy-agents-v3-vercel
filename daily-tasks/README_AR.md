# الأتمتة اليومية للمهام الواردة

يدخل على نظام المهام، يقرأ المهام الواردة، يستخرج بيانات كل معاملة من ملف الـPDF
المرفق، يسجلها في ملفي إكسل (العلاج الطبيعي / الجهاز الهضمي) بشريحة مستقلة لكل يوم،
ثم يفتح كل مهمة ويضعها **تحت التنفيذ** مع كتابة الملاحظة والحفظ.

---

النظام المستهدف: **نظام متابعة المهام - جامعة الملك سعود** (`ttn.ksu.edu.sa`).

## من أين تأتي البيانات

عنوان المهمة في صفحة المهام الواردة يحمل الحقول جاهزة مفصولة بشرطات:

```
طلب تقرير انجليزي - خلود سالم محمد القحطاني - 1065170 - ماجد الماضي - الجهاز الهضمي
      نوع الطلب         اسم المريض          رقم الملف      الطبيب        القسم
```

فاسم المريض ورقم الملف والقسم تقرأ من العنوان مباشرة (وبعض المهام بلا اسم طبيب،
والسكربت يتعامل مع الشكلين). رقم المهمة يقرأ من `الرقم: 144800006202`، والتاريخ
الميلادي من الجزء الذي يلي «الموافق». والـPDF المرفق يستخدم لباقي المعلومات كما طلبت.

نتيجة ذلك أن السكربت لا ينهار لو كان المرفق ممسوحا ضوئيا أو مفقودا: الحقول الأساسية
مضمونة من العنوان.

## قبل أي شيء: نقطتان مهمتان

**1. لا يمكن تشغيل هذا في السحابة.** هذه بيئة مؤقتة تمسح بعد انتهاء الجلسة، ولا تصل
لشبكة الجامعة. الجدولة اليومية يجب أن تكون **على جهازك أو على جهاز يعمل باستمرار**
داخل الشبكة التي تصل للنظام.

**2. غيّر كلمة المرور.** كلمة المرور التي أرسلتها في المحادثة يجب اعتبارها مكشوفة.
غيّرها من النظام، وضع الجديدة في ملف `.env` فقط. هذا الملف مستثنى من Git ولن يرفع.
لا توجد أي كلمة مرور مكتوبة داخل أي ملف في هذا المشروع.

## التركيب (مرة واحدة)

```bash
cd daily-tasks
npm install
npm run setup          # يحمل متصفح Chromium
cp .env.example .env   # على ويندوز: copy .env.example .env
```

افتح `.env` وعبئ:

| القيمة | الشرح |
|---|---|
| `SYSTEM_BASE_URL` | معبأ مسبقا: `https://ttn.ksu.edu.sa` |
| `TASKS_URL` | معبأ مسبقا: `https://ttn.ksu.edu.sa/employee/tasks/defaultInbox` |
| `SYSTEM_USERNAME` | اسم المستخدم في النظام |
| `SYSTEM_PASSWORD` | كلمة المرور الجديدة بعد تغييرها |

تأكد أن كل شيء يعمل على جهازك قبل لمس النظام:

```bash
npm run selftest
```

يجب أن تظهر `14/14 فحص ناجح`. فحص محلي لا يتصل بالنظام إطلاقا، ومن ضمنه قراءة عناوين
مهام حقيقية منقولة من صندوقك والتأكد أنها تصنف صحيحا.

## الخطوة الأهم: ربط السكربت بصفحات نظامك

```bash
npm run discover
```

يدخل على النظام ولا يعدل أي شيء، ثم يحفظ في مجلد `screenshots/`:

- لقطات شاشة لكل صفحة
- ملف `discovery.md` فيه أسماء الأزرار والحقول و**أرقام أعمدة الجدول**

افتح `discovery.md` وانقل منه القيم إلى `config/selectors.json`. أهم موضعين:

**أ) أعمدة جدول المهام** — رقم العمود يبدأ من صفر:

```json
"columns": {
  "taskNumber": 0,
  "patientName": null,
  "fileNumber": null,
  "subject": 1,
  "sender": 2,
  "date": 3
}
```

ضع `null` لأي عمود غير موجود في الجدول، وسيستخرج من الـPDF بدلا عنه.

**ب) أزرار صفحة التفاصيل** — انقل النص كما يظهر في نظامك حرفيا:

```json
"inProgressButton": ["text=تحت التنفيذ"],
"saveButton":       ["text=حفظ"]
```

كل حقل عبارة عن **قائمة محاولات** تجرب بالترتيب حتى تنجح واحدة، فيمكنك ترك البدائل
كما هي وإضافة الصحيح في أولها.

> جرب على نظام وهمي أولا إن أحببت: `node mock/server.js` في طرفية، ثم اضبط
> `SYSTEM_BASE_URL=http://127.0.0.1:8910/login` وشغل السكربت. لا علاقة له بنظامك الحقيقي.

## التشغيل

```bash
npm run run:dry     # تجربة: يقرأ ويسجل في الإكسل ولا يلمس النظام إطلاقا
npm run run:live    # تنفيذ فعلي: يضغط "تحت التنفيذ" ويكتب الملاحظة ويحفظ
```

**ابدأ بـ `run:dry` وافتح ملفات الإكسل وتأكد أن الأسماء وأرقام الملفات صحيحة.**
لا تنتقل للتنفيذ الفعلي قبل ذلك — الخطوة الثانية تعدل حالة معاملات حقيقية.

عند الرضا عن النتيجة، ضع `AUTO_MARK_IN_PROGRESS=true` في `.env` لتصبح الجدولة اليومية
تنفذ فعليا، أو أبقها `false` لتظل تسجل فقط.

### المتراكم: عندك أكثر من ألف مهمة واردة

صندوقك فيه 1074 مهمة واردة و599 متأخرة. لا تطلق السكربت عليها كلها من أول مرة.
الترتيب الموصى به:

1. `MAX_TASKS_PER_RUN=10` مع `npm run run:dry` — افتح الإكسل وتأكد أن الأسماء وأرقام
   الملفات والتصنيف صحيحة.
2. `MAX_TASKS_PER_RUN=10` مع `npm run run:live` — تأكد أن «تحت التنفيذ» تسجلت فعلا في
   النظام على عشر معاملات فقط.
3. ارفعه تدريجيا (50 ثم 200) لتصفية المتراكم على عدة تشغيلات.
4. بعد التصفية أعده لرقم يومي معقول مثل `MAX_TASKS_PER_RUN=100`.

السكربت يعالج على دفعات (`BATCH_SIZE=25`): بعد كل دفعة يكتب الإكسل ويحفظ سجل الحالة.
لو انقطع الاتصال في المنتصف لا يضيع إلا الدفعة الجارية، وما نفذ قبلها لا يعاد.

للسرعة: أول مهمة تستغرق نحو نصف دقيقة لأن السكربت يتعرف على أزرار النظام، ثم يحفظ ما
نجح ويعالج بقية المهام في نحو ثانية لكل مهمة.

## الجدولة اليومية الساعة 3 عصرا

**ويندوز** (من PowerShell بصلاحية مسؤول):

```powershell
powershell -ExecutionPolicy Bypass -File scheduler\install-task.ps1
```

يسجل مهمة يومية 15:00. لتجربتها فورا:
`Start-ScheduledTask -TaskName "المهام اليومية - العلاج الطبيعي والجهاز الهضمي"`

**لينكس / ماك**: افتح `scheduler/crontab.txt` واتبع التعليمات داخله.

ملاحظتان:
- الجهاز يجب أن يكون يعمل الساعة 3. الخيار `-StartWhenAvailable` يشغل المهمة عند أول
  تشغيل للجهاز إن كان مطفأ في وقتها.
- ضع `HEADLESS=true` في `.env` للجدولة، حتى لا تقفز نافذة متصفح أثناء عملك.

## المخرجات

في مجلد `output/`:

| الملف | المحتوى |
|---|---|
| `مرضى_العلاج_الطبيعي.xlsx` | معاملات العلاج الطبيعي |
| `مرضى_الجهاز_الهضمي.xlsx` | معاملات الجهاز الهضمي |
| `معاملات_غير_مصنفة.xlsx` | ما لم يتضح قسمه — لا تضيع أي معاملة بصمت |

**داخل كل ملف شريحة مستقلة لكل يوم باسم `2026-07-27`**، فمرضى الأربعاء منفصلون تماما
عن مرضى الثلاثاء، والشرائح تتراكم في نفس الملف.

الأعمدة: م، رقم المهمة، اسم المريض، رقم الملف، القسم، نوع الطلب، التشخيص، الطبيب
المحول، الجهة المرسلة، تاريخ المعاملة، الملخص، حالة المعاملة، مصدر البيانات، وقت
التسجيل، رابط المهمة، ملف الـPDF.

الصفوف **الملونة بالأصفر** ينقصها اسم المريض أو رقم الملف وتحتاج مراجعة يدوية.

مجلدات أخرى: `pdfs/` نسخ المرفقات، `logs/` سجل كل تشغيلة، `state/` سجل المعاملات
المنفذة. جميعها مستثناة من Git لأنها تحتوي بيانات مرضى.

## نقاط مهمة في السلوك

- **لا تكرار.** المعاملة المسجلة سابقا تتخطى في التشغيلات التالية، سواء أعدت التشغيل
  في نفس اليوم أو عمل المجدول مرتين.
- **التسجيل قبل التنفيذ.** يكتب الإكسل أولا ثم يضغط "تحت التنفيذ"، فلا تنفذ معاملة
  دون أن تسجل. بعد التنفيذ تحدث خانة الحالة إلى «تحت التنفيذ».
- **ملف PDF ممسوح ضوئيا؟** إن كان المرفق صورة بلا نص، يستخدم `OPENAI_API_KEY` (اختياري)
  لقراءة البيانات منه. بدون المفتاح تسجل المعاملة بحالة «يحتاج إدخال يدوي» وتلون بالأصفر.
- **لا يستخرج رقم الهوية الوطنية** ولا أي بيانات دخول، ولا تظهر كلمة المرور في السجلات.
- **التصنيف بالكلمات المفتاحية** في `config/selectors.json` تحت `classification`. أضف أي
  مصطلح يستخدمه نظامك، فيتحسن التصنيف فورا.

## إذا توقف السكربت

رسائل الخطأ تذكر اسم الحقل الذي فشل والمحددات التي جربها. الحل دائما واحد:
شغل `npm run discover`، افتح `screenshots/discovery.md` واللقطات، وصحح المحدد في
`config/selectors.json`. لا حاجة لتعديل أي ملف برمجي.

| المشكلة | الحل |
|---|---|
| «لم يتأكد نجاح تسجيل الدخول» | راجع بيانات `.env`، وعدل `login.successIndicator` ليطابق عنصرا يظهر بعد الدخول فقط |
| «لم يقرأ السكربت أي صف» | عدل `taskList.rowContainer` |
| «لم يوجد زر تحت التنفيذ» | عدل `taskDetail.inProgressButton` بالنص الحرفي في نظامك |
| أعمدة الإكسل فارغة | راجع `taskList.columns`، أو اترك القيم `null` ليعتمد على الـPDF |
| المتصفح لا يعمل | ضع `CHROMIUM_PATH` في `.env` مشيرا إلى Chrome أو Edge المثبت عندك |
